# Implementation drift against SPEC 0.2.2 / container 1.2 — audit 2026-08-14

Measured against `SPEC.md` v0.2.2, `CODEC_REGISTRY.md`, and `schema/rpk_metadata.schema.json`, using the
two shipped datasets: **canonical pores** (600 packs) and **Winther G6 axons** (29 walk packs + 29 field
companions).

## Conformance status: the containers are fine

| artifact | schema validation | notes |
|---|---|---|
| canonical pack (`cylinder/d10.00um.rpk`) | **PASS** | one extra top-level key, `grid` |
| Winther walk pack (`winther_G6_axon06.rpk`) | **PASS** | no extra keys |
| Winther field companion (`*.field.rpk`) | **FAIL** (3 required keys absent) | not a conformant pack — see D6 |

Both producers declare `rpk_schema_version: "1.1"` while the spec now describes `"1.2"`. Since 0.2.1 added
only an OPTIONAL field and 0.2.2 is clarification-only, the packs remain conformant (§4 of SPEC states all
`0.1.x`/`0.2.x` packs do); the declared version is simply behind. `walk_params.substrate_frame` (added in
0.2.1) is already present.

**So the drift is not in the container or the metadata schema. It is concentrated in the codec registry.**

## D1 — Position representation: the registry documents a form the reader now rejects

`CODEC_REGISTRY.md` lists `temporal_dct` with stored key **`dct_coeffs`**, shape `(N_w, K, 3)`.

Both producers now write **one tensor per axis** — `pos_x`, `pos_y`, `pos_z`, each `(N_w, K)` — declared via
new metadata `compression.position_layout = "axis_per_tensor"` and `compression.position_axes`. The reason
is byte-range economics over HTTP: in the combined layout an axis slice is a strided gather (measured
169.8 ms against 16.3 ms to read the *entire* tensor), whereas per-axis tensors make an axis choice and a
walker prefix compose into a single contiguous range.

**The sharp edge:** the reference reader (`dmipy_sim.compression.read_position_coeffs`) now *raises* on a
`dct_coeffs` pack, deliberately, to keep a single format in circulation. A third-party pack written to the
registry as it stands is therefore unreadable by the reference implementation. Registry and reader
disagree, and the registry is the normative one.

**Action:** register `axis_per_tensor` as the current representation of `temporal_dct` (stored keys, the two
metadata fields), and state explicitly whether `dct_coeffs` is (a) deprecated-but-readable, or (b) removed.
Pick one; today the documents say (a) and the code does (b).

## D2 — `boundary_local_time`: an unregistered codec, and two key names for it

Registry offers **sparse CSR** (`blt_counts`, `blt_cols`, `blt_qvals`) or **dense int8** (`blt_dense_q`),
selected by `meta.mode`, and argues *against* low-rank/DCT for this channel ("not low-rank … low-rank needs
`K>32` and still misses the noise floor").

Shipped reality is a **temporal DCT**:

| dataset | stored keys | params |
|---|---|---|
| canonical pores | `blt_dct` | `channels.boundary_local_time.mode = "temporal_dct"`, `K = 64` |
| Winther G6 | `blt_dct_coeffs`, `blt_endpoint` | — |

Two problems: the codec is unregistered, and **our own two datasets use different key names for it**, which
is exactly what a registry exists to prevent.

**Action:** converge on one key set, register it with the measurement that overrides the registry's stated
objection (the canonical packs' surface fidelity is `err_surface` ~1e-4 against a median surface floor
~2e-4 — note this is *not* uniformly below floor: 44/600 packs have codec error at or above their own
surface floor, which belongs in the registration).

## D3 — `susc_field_basis`: shipped as a different channel than the registry defines

Registry baseline: raw **float16**, key `susc_field_basis`, shape `(N_w, N_t, 13)`, with a shared linear
basis noted as "the intended size optimization — registered later once measured".

Shipped: key **`susc_path_dct`**, float16, shape `(N_w, 12, K)`. Three departures beyond compression:

1. **Temporal DCT** along the walk instead of raw — the anticipated optimization, now measured and shipped
   but still unregistered.
2. **12 components, not 13.** `P_zz` is not stored; it is reconstructed from the trace identity
   `P_xx + P_yy + P_zz = 3·iso_local`, which holds exactly for an un-apodised source (verified to
   4.7e-16). The encoder checks the identity and stores all components if it fails. The spec's channel
   table says 13 and does not mention the identity.
3. **`K` is a capability, not a precision knob.** The field along a path is broadband, so `K` does not
   reproduce the field — it reproduces the *phase*, because the sequence gate is narrowband. The measured
   requirement is `K >= 2·n_refocus`, recorded as `max_refocus_pulses`. Nothing in the spec carries this
   semantics, so a replayer cannot tell from the metadata that a denser refocusing train is out of range.

**Action:** register the codec; add the trace identity as a stated channel invariant (§5.3); and give the
envelope a place for the refocusing-train limit (see D5).

## D4 — Producer metadata extensions are unnamespaced and inconsistent

`grid` (canonical) carries `eps`, `worst_residual`, `ladder`, `prefix_tiers`, `envelope`. Permitted —
schema `additionalProperties: true` — but the spec defines an extension convention only for *channels*
(`x_` prefix) and says nothing about metadata keys.

Worse, the same concept has two names across our datasets: canonical `grid.prefix_tiers` versus Winther
`compression.precision_tiers`, both meaning "measured walker prefix for each target epsilon".

**Action:** define an `x_`-style convention for metadata (or promote these to first-class keys) and pick one
name for the precision-tier table.

## D5 — SPEC GAP: the envelope cannot declare a bandwidth

`replay_envelope.acquisition` has `b_max`, `ogse_periods`, `B0_list`. There is **no field for the frequency
band the pack represents**, which the audit found to be the single most important limit of a gradient-tier
pack.

Worse, `ogse_periods` is actively misleading as a frequency statement. The reference battery builds OGSE as
`cos(2*pi*nper*t/T)` over the **whole record**, so the canonical packs' `ogse_periods: [2]` is a **10 Hz**
oscillation — while the packs' real usable limit is ~200 Hz and their hard wall ~250 Hz. A consumer reading
`ogse_periods: [2]` reasonably concludes "OGSE is supported"; the honest statement is a frequency.

The band is a closed-form property of the representation: replay forms the phase as
`sum_{k<K} gamma*dt*Ghat_k . Chat_k`, so mode `k` corresponds to `f = k/(2*T_max)` and

```
f_band_nominal = K / (2*T_max)          f_usable ~ f_band_nominal / 1.6        (measured safety factor)
```

Truncation error is predictable *before replay* as
`sigma_trunc = sqrt(sum_{k>=K} sum_a W[k,a]^2 <Chat[k,a]^2>)` with `W = compile_scheme(G, dt, n_t)`;
calibrated against 135 measured deviations it separates pass from fail at `sigma_trunc ~ 0.3 rad`
(r = 0.913). `<Chat_k^2>` above the band is substrate-independent (local diffusion; measured decay
exponent 1.281–1.384 across three shapes and 2–20 um, spread 0.045), so a single calibration serves every
pack.

**Action (proposed for 0.3.0):** add `replay_envelope.acquisition.f_max_hz` — REQUIRED when `gradient` is
declared — and make §13 conformance require a replayer to refuse, not extrapolate, above it. `ogse_periods`
should either be deprecated in favour of it or re-specified to state the frequency directly.

## D6 — Sidecars use the pack extension without being packs

`<id>.field.rpk` (255 MiB per axon) fails schema validation on three required keys (`walk_params`,
`compression`, `replay_envelope`) and carries its own `kind`/`field` keys. It is a legitimate artifact — the
static field grid, needed to regenerate the path channel at a different `K` or for a new walk — but it is
not a replay pack and should not claim the extension.

**Action:** define a minimal sidecar profile (`kind` + `provenance` + `license` + `citation`) or give
sidecars a distinct extension.

## D7 — No place for per-family certification against an independent reference

`fidelity.per_family` exists, but it means *codec versus its own master walk*. The audit produced a
different and more useful quantity: per-acquisition-family deviation against an **independent** analytic
reference (PGSE 5.0e-3 worst over 600 packs; PGSTE 6.4e-3; CPMG 2.7e-2; OGSE<=200Hz 8.6e-2). It currently
ships as a sidecar, `family_certification.json`, because the schema has nowhere for it.

**Action:** add an OPTIONAL `certification.per_family` block (family -> worst/median deviation, reference
used, acquisition list), distinct from `fidelity`, which stays a compression statement.

## D8 — Storage note for C3 producers: a bounding box is the wrong container for a tube

Not a conformance issue, but it belongs with the registry. The field companion stores 13 components over a
`97 x 89 x 1191` grid = 10.28 M voxels = 255 MiB. The box is already tight (mesh bbox + 1.6 um), yet the
axon fills only **7.9%** of it, because a real axon *meanders* ~±5 um in x/y over 152 um of length and a
bounding box around a meandering tube is mostly empty.

Measured alternatives (axon06, distance to the outer myelin surface):

| representation | fraction kept | size | factor |
|---|---|---|---|
| full box (today) | 100% | 255 MiB | 1x |
| voxels within 2 voxels (0.26 um) of tissue | 3.9% | 9.8 MiB | 26x |
| voxels within 0.5 um of tissue | 8.1% | 20.6 MiB | 12x |
| per-z-slice window, 2-voxel margin | 13.9% | 35.5 MiB | 7.2x |

A bitmask over the retained voxels costs ~1.2 MiB, so the masked forms keep their advantage. The per-slice
window is the simplest (median window 34x35 voxels, index overhead 0.02 MiB) and stays randomly
addressable. **Recommendation:** register a masked/windowed grid form for `susc_field_*`, and state that the
solve domain (padding, here 6 um) and the *stored* domain are independent — the field must be solved on the
padded box and MAY be cropped afterwards to the walker-reachable region plus an interpolation margin.
